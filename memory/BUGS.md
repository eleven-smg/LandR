## Verification rules learned the hard way

- Never trust `list_tables.rows`; run `count(*)`.
- `create index if not exists` matches on **name**; `create table if not exists` does **not** add columns.
- Cached web fetches are not evidence of production state, in either direction. Proven again on
  26 Sep: `web.loadPage` served the pre-LandR scaffold for `/` and a stale "does not exist" for
  `/ava`. The tell is an artefact the repo no longer contains. The client's browser and the
  `page_views` counts are ground truth.
- Country detection and geo features cannot be tested locally — only on the deployed URL.
- A layout gate protects pages only. **Route handlers and server actions never run a layout**, so
  each one needs its own `requireDashboardAccess` call. This was the single largest class of defect
  in the project.
- A feature that widens a query past the handle in the address bar (a collection, a group, a
  workspace-wide report) must narrow the page list by the pages the viewer manages, or one model
  reads another's numbers. Scope the **option lists** too, not just the data (F24). When two screens
  need the same answer, put the rule in one helper — the filter and the export disagreed for a whole
  day because each had its own copy (F25).
- **A settings field that no code path reads is worse than a missing feature**, because the UI
  teaches the client a behaviour that does not exist (F18). When adding a control, trace it to the
  visitor path before describing it to anybody.
- A table with no owner column cannot be shown to more than one account (F21).
- **A migration is not a feature.** Columns with no code behind them read as done in the schema and
  do nothing in the product (F22). Ship the columns and the code in the same session, or file the
  gap as a P1 bug the moment the migration lands.
- **A whole-file resend is a text pipeline, so escapes get mangled.** A `\uXXXX` escape in the source
  arrived doubled twice in one session and would have printed literally on screen (`f8179966`,
  `ef1d6386`). Prefer HTML entities such as `&uarr;` in JSX, and **always re-read the file after a
  push** — the stray-brace incident (`7ae2484e`) was the same class of error. Where a literal
  character will do, write the character: F27 replaced the three `\u2014` escapes in `users/page.tsx`
  with real em dashes so the file has no escapes left to mangle.
- **Read what the class or column is actually for before filing the symptom** (F26). `.nav-current`
  was filed as the active-tab highlight; it is the current-model label, and the two are different
  elements with different rules.
- A redirect destination written for one screen is a bug on the second screen that reuses the
  action (F27). When an action can be called from more than one page, the destination is an
  argument, and the page it returns to has to render whatever the action reports.
- **The signed-out pages are a surface too.** Every rewording pass from 22 Aug to 26 Sep swept the
  dashboard and missed `app/page.tsx`, the page a stranger reads first, which went on advertising
  geoblocking for a month after the behaviour changed (F28). When a feature's meaning changes, sweep
  the home page, `/signin` and `/register` in the same pass — and check every count in marketing copy
  against what actually shipped, because "three templates" was wrong too.
